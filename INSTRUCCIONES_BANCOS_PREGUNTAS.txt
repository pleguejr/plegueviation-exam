Este documento contiene las instrucciones exactas y la POLÍTICA OFICIAL para:
1. Generar bancos de preguntas con rigor técnico basados EXCLUSIVAMENTE en manuales.
2. Cómo funciona el ciclo automático de sincronización (GitHub + Vercel).
3. Cómo actualizar tus dispositivos con un solo clic o a través del asistente.
4. Instalar y usar la aplicación en tu iPhone o iPad (100% Offline).


--------------------------------------------------------------------------------
1. POLÍTICA ESTRICTA DE CREACIÓN DE PREGUNTAS (ESTÁNDAR TRE / COMANDANTE)
--------------------------------------------------------------------------------

Para garantizar la máxima calidad técnica para el entrenamiento operacional:

1. EXCLUSIVIDAD DOCUMENTAL (GROUND TRUTH):
   - Queda terminantemente PROHIBIDO inventar o extrapolar preguntas, límites o cifras.
   - Toda pregunta, opción y distractor debe estar extraída LITERALMENTE de los
     manuales de referencia aportados (AFM, FCOM, QRH, SOPM, DDPM, MEL, MOA, MOB, Normativa).

2. ESTRUCTURA DE OPCIONES (1 CORRECTA + 3 DISTRACTORES REALISTAS):
   - Exactamente 4 opciones ("A", "B", "C", "D").
   - Exactamente UNA opción con "is_correct": true.
   - Exactamente TRES distractores realistas ("is_correct": false) basados en:
     * Confusiones operacionales habituales en auditorías o simulador.
     * Límites correspondientes a otra fase de vuelo o configuración adyacente.
     * Cifras o umbrales técnicos verosímiles (prohibidas opciones absurdas).

3. CITAS Y REFERENCIAS OBLIGATORIAS CON PÁGINA:
   - Toda explicación debe incluir en el array "references":
     * Manual y edición/revisión exacta.
     * Capítulo, Sección y Párrafo.
     * Número de Página física del documento.
     Ejemplo: "Tecnam P2010 TDI AFM - Ed.2 Rev.13 - Section 5: Performance (Pág. 5-10)"


--------------------------------------------------------------------------------
2. CÓMO FUNCIONA EL CICLO ACTUAL DE ACTUALIZACIÓN (LOCAL -> GITHUB -> VERCEL -> IPAD)
--------------------------------------------------------------------------------

El sistema está configurado para que la actualización sea en cadena y automática:

  [TUS PREGUNTAS JSON]
          │
          ▼
  1. Guardar en 'banks/...'
          │
          ▼
  2. Sincronizar con GitHub (git push)
          │
          ▼
  3. Vercel detecta el cambio automáticamente en la nube (~20 segundos)
          │
          ▼
  4. Tu iPad / iPhone / PC se actualiza solo en cuanto abre la app con internet
     y guarda las preguntas para seguir usándolas 100% OFFLINE en modo avión.

3. ¿EL "GIT PUSH" ES AUTOMÁTICO O TIENES QUE HACERLO TÚ?
--------------------------------------------------------------------------------

CASO A: Si estás trabajando conmigo en este chat:
  - ¡Es 100% AUTOMÁTICO!
  - Cada vez que me pidas crear preguntas, modificar el diseño o importar un lote,
    yo mismo ejecuto 'build_banks.py', 'git commit' y 'git push' por ti.

CASO B: Si creas los archivos JSON tú por tu cuenta en tu PC:
  - Haz doble clic en: 'actualizar_banco.bat'.
  - Compila y sube a GitHub y Vercel en 2 segundos.

CASO C: Si estás en movilidad en tu iPad o iPhone (sin PC):
  - En la propia app del iPad, pulsa el botón "Importar IA", pega el JSON
    y pulsa "Validar e Importar".

4. PLANTILLA DE PROMPT MAESTRO PARA NOTEBOOKLM / GEMINI
--------------------------------------------------------------------------------

[COPIA DESDE AQUÍ]
--------------------------------------------------------------------------------
Actúa como un examinador TRE/TRI y evaluador de prueba de Comandante.
Tu objetivo es formular un lote de preguntas de opción múltiple con máxima
precisión técnica y operacional basadas EXCLUSIVAMENTE en las fuentes adjuntas.

REGLAS ESTRICTAS:
1. FIDELIDAD ABSOLUTA: Cero invención. Extrae los datos literalmente del texto adjunto.
2. 4 OPCIONES: Exactamente UNA opción con "is_correct": true y TRES distractores
   realistas ("is_correct": false) basados en errores comunes o límites adyacentes.
3. REFERENCIA OBLIGATORIA: Cita en "references" el Manual, Edición, Capítulo,
   Párrafo y Número de Página exacta de la fuente.
4. Devuelve ÚNICAMENTE un bloque de código JSON válido, sin texto introductorio.

ESTRUCTURA DEL JSON:
[
  {
    "id": "PREFIJO-NUMERO",
    "subject_id": "CODIGO_TEMA",
    "learning_objective": "Capítulo, Párrafo y Tema del Manual",
    "stem": "Enunciado claro y profesional de la pregunta...",
    "options": [
      { "id": "A", "text": "Texto opción A...", "is_correct": true },
      { "id": "B", "text": "Texto opción B (distractor realista)...", "is_correct": false },
      { "id": "C", "text": "Texto opción C (distractor realista)...", "is_correct": false },
      { "id": "D", "text": "Texto opción D (distractor realista)...", "is_correct": false }
    ],
    "explanation": {
      "text": "Explicación técnica detallada citando el porqué según el manual...",
      "references": [
        "Manual / Edición / Capítulo / Párrafo / Página exacta"
      ]
    },
    "metadata": {
      "difficulty": 0.4
    }
  }
]

INSTRUCCIÓN ESPECÍFICA PARA ESTE LOTE:
- Tema/Sección a extraer: [ESCRIBE AQUÍ EL CAPÍTULO O PÁGINAS]
- subject_id a utilizar: [ESCRIBE AQUÍ EL SUBJECT_ID DE LA TABLA]
- Rango de IDs: [EJEMPLO: P2010-LIM-001 al P2010-LIM-015]
- Cantidad de preguntas: [EJEMPLO: 15 preguntas]
--------------------------------------------------------------------------------
[HASTA AQUÍ]
